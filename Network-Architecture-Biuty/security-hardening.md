## Overview

Security hardening to proces wzmacniania bezpieczeństwa systemów, urządzeń, aplikacji i infrastruktury w celu zmniejszenia liczby podatności oraz ograniczenia możliwości przeprowadzenia skutecznego ataku.

Hardening obejmuje działania wykonywane przed wystąpieniem incydentu, aby zmniejszyć prawdopodobieństwo naruszenia bezpieczeństwa oraz ograniczyć jego potencjalne skutki.




## Network Hardening

Network hardening polega na wzmacnianiu zabezpieczeń infrastruktury sieciowej poprzez ograniczanie niepotrzebnych usług, zamykanie niepotrzebnych portów oraz stosowanie bezpiecznej konfiguracji urządzeń.

Przykładowe działania:

- wyłączenie niepotrzebnych usług,
- zamknięcie nieużywanych portów,
- zmiana domyślnych haseł,
- stosowanie silnego uwierzytelniania,
- regularne aktualizowanie firmware i oprogramowania,
- ograniczenie dostępu administracyjnego,
- segmentacja sieci za pomocą VLAN,
- odpowiednia konfiguracja firewalla,
- monitorowanie urządzeń i ruchu sieciowego.

Celem network hardening jest zmniejszenie powierzchni ataku oraz ograniczenie możliwości wykorzystania podatności.



## Security Measures

Security measures to działania i mechanizmy stosowane w celu ochrony systemów, urządzeń, sieci i danych.

Przykładowe środki bezpieczeństwa:

- Firewall — kontroluje dozwolony ruch sieciowy.
- MFA — wymaga dodatkowego elementu uwierzytelniania.
- Access Control — ogranicza dostęp do zasobów zgodnie z uprawnieniami.
- Encryption — chroni dane poprzez ich szyfrowanie.
- Network Segmentation — oddziela różne części infrastruktury sieciowej.
- Logging and Monitoring — umożliwia rejestrowanie i analizowanie aktywności.
- Regular Updates — ograniczają ryzyko związane ze znanymi podatnościami.

Skuteczna ochrona wymaga stosowania wielu warstw zabezpieczeń zamiast polegania na jednym mechanizmie.



## System Hardening

System hardening polega na zabezpieczaniu systemów operacyjnych i urządzeń poprzez ograniczenie ich powierzchni ataku oraz usunięcie niepotrzebnych funkcji.

Przykładowe działania:

- regularne instalowanie aktualizacji bezpieczeństwa,
- usuwanie niepotrzebnego oprogramowania,
- wyłączanie nieużywanych usług,
- stosowanie silnych haseł,
- ograniczanie uprawnień użytkowników,
- zabezpieczanie kont administracyjnych,
- włączanie odpowiedniego logowania i monitorowania,
- stosowanie bezpiecznej konfiguracji systemu.

System powinien udostępniać tylko te funkcje i usługi, które są rzeczywiście potrzebne do jego działania.



## Application Security

Application security obejmuje działania mające na celu ochronę aplikacji przed podatnościami i nieautoryzowanym dostępem.

Przykładowe działania:

- regularne aktualizowanie aplikacji i zależności,
- bezpieczna konfiguracja aplikacji,
- kontrola dostępu,
- bezpieczne przechowywanie danych uwierzytelniających,
- szyfrowanie wrażliwych danych,
- monitorowanie błędów i podejrzanej aktywności,
- testowanie aplikacji pod kątem podatności.

Bezpieczna aplikacja powinna być projektowana, konfigurowana i utrzymywana z uwzględnieniem zasad bezpieczeństwa.



## Cloud Security

Cloud security obejmuje działania mające na celu ochronę danych, aplikacji, usług i infrastruktury działających w środowisku chmurowym.

Przykładowe działania:

- odpowiednia kontrola dostępu,
- stosowanie zasady least privilege,
- MFA dla kont użytkowników i administratorów,
- szyfrowanie danych,
- monitorowanie aktywności,
- bezpieczna konfiguracja usług chmurowych,
- regularne aktualizacje i zarządzanie podatnościami.

W środowisku cloud ważne jest również prawidłowe skonfigurowanie uprawnień i zasobów, ponieważ błędna konfiguracja może prowadzić do nieautoryzowanego dostępu lub ujawnienia danych.



## Cloud Infrastructure Risks

Środowiska chmurowe mają specyficzne zagrożenia związane z konfiguracją, dostępem i zarządzaniem zasobami.

Przykładowe ryzyka:

- błędna konfiguracja zasobów,
- nadmierne uprawnienia użytkowników,
- brak MFA,
- publiczny dostęp do wrażliwych danych,
- niezabezpieczone interfejsy API,
- brak odpowiedniego monitorowania,
- nieaktualne lub podatne komponenty.

Ograniczanie tych ryzyk wymaga odpowiedniej konfiguracji, kontroli dostępu, monitorowania oraz regularnego przeglądu zabezpieczeń.



## Preventing Future Attacks

Security hardening ma na celu nie tylko reagowanie na istniejące problemy, ale również zmniejszanie prawdopodobieństwa wystąpienia przyszłych incydentów.

Przykładowe działania:

- regularne aktualizowanie systemów i urządzeń,
- zarządzanie podatnościami,
- ograniczanie uprawnień zgodnie z zasadą least privilege,
- stosowanie MFA,
- segmentacja sieci,
- bezpieczna konfiguracja firewalla,
- monitorowanie i analiza logów,
- regularne przeglądy konfiguracji,
- testowanie zabezpieczeń,
- szkolenie użytkowników.

Regularny hardening pomaga organizacji reagować na zmieniające się zagrożenia i ograniczać powierzchnię ataku.
